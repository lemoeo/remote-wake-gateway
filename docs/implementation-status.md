# 首版实现状态

版本：0.1.0-dev，2026-11-11。

新安装默认监听 `127.0.0.1:9000`；管理员首次设置和本机密码恢复均接受 6–72 字节密码。已有数据目录保留保存的监听地址和密码，不自动迁移。相关测试覆盖 5 / 6 / 72 / 73 字节边界、六字节密码的 HTTP 初始化与登录、CLI 密码恢复及旧监听配置兼容。

## 验证方式

已通过：`go test -race ./...`、`go vet ./...`、前端 TypeScript 检查、Vite 生产构建与 17 项前端请求 / 网卡配置 / 批量调度与面板状态测试。本机 macOS arm64 可执行文件及 Linux amd64 / arm64 交叉编译产物位于 `bin/`。

Windows 适配已在 macOS 上通过完整 Go 竞态回归，Windows amd64 / arm64 全部测试包编译及对应 `go vet` 检查通过；这些交叉编译检查不执行 Windows 测试。已配置 `windows-latest` 原生 CI，专项测试检查实际 ACL、替换失败时旧文件不变且临时文件清理、Unicode / 空格路径、Socket 广播选项和跨进程互斥 / 强制退出后解锁。当前会话没有 Windows 运行环境，尚未执行该原生 CI；Windows arm64 和真实 LAN 广播也需目标设备验收。Windows 写入采用先同步内容、再替换的流程，不承诺与 Unix 目录同步完全相同的断电保证。

Go 测试包括真实本机 HTTP/TCP/UDP 服务和模拟 Apple DH 服务端。DH 测试由服务端独立计算共享密钥并解密用户名/密码字段，验证正确线格式、安全类型选择和认证后不发送 ClientInit。测试还覆盖认证拒绝、限流、持久化失败不提交密码、错误密码跨新命令及跨重启冷却。

任务测试覆盖幂等、同设备互斥、浏览器请求上下文取消后任务继续、凭据绑定修改、显式取消、重启后不重放和接受任务前磁盘写失败。HTTP 流程覆盖初始化、登录、Origin、CSRF、设备配置、幂等任务查询、密码不回传、公开导出和退出。

浏览器通过独立的临时预览数据目录验证登录、新建设备、编辑回填和 Mac 表单；预览设备均为示例，未向其发送实际唤醒命令。截图见 [设备管理界面](screenshots/gateway-preview.png)。

网卡选择调整已在浏览器验证：默认“由系统选择”、保存 `255.255.255.255`、切换手动网卡时保留受限广播、点击广播地址建议，以及保存与所选网卡子网不一致的自定义地址。截图见 [网卡配置与非阻断提示](screenshots/network-interface-preview.png)。新增后端测试覆盖实际回环 UDP 发送、手动网卡的多 IPv4 地址选择、受限广播的专用策略例外，以及失效显式网卡不回退；未向真实 LAN 发送测试广播。

设备 ID 调整已验证：Web 不填写 ID 即可创建，类型选择与编辑回填继续保留，普通卡片不再显示 ID；表单截图见 [设备类型保留与 ID 隐藏](screenshots/device-form-preview.png)。自动化覆盖省略 ID 的 HTTP 创建、导出保留 ID / 类型，以及自动 ID 对应的凭据和历史在重命名、修改类型、服务重启后继续有效。

## 与完整规划的交付边界

- MQTT、云端、outbox、Android、WebSocket 属于后续阶段，本次没有加入空模块。
- 文件锁实现覆盖 Linux / macOS / FreeBSD / Windows，UDP 广播使用 Go 标准库。macOS 回归已通过；Windows 原生 CI 已配置，尚待远端运行；Linux / FreeBSD 的新增路径与目标设备效果仍需对应环境验证。
- 使用规范 JSON 任务文件作为历史来源，尚未增加可重建 JSONL 归档。默认 stdout 日志，尚无文件日志轮转器。
- schema 不兼容时明确拒绝读取；尚无自动版本迁移器。备份和升级目前按 README 手工执行。
- 任务容量采用数量上限（10000 条，每文件另有 4 MiB 上限），尚无独立的任务目录总字节设置。
- 配置保存后的监听地址、public_url、并发/队列和保留策略需重启生效；名称和允许目标网段即时生效。设置页面会提示重启。
- CLI 初次设置密码、Web 初始化及本机停服恢复命令均可用；尚无 Web 管理员密码修改接口。
- 未测量 ARM Linux 的 RSS 和长期闪存写入量；未在真实 PC、Mac、NAS、树莓派或 OpenWrt 上验收。交叉编译通过不代表硬件兼容。
- 本机没有 Docker 运行环境，Dockerfile / Compose 和 systemd 模板尚未进行部署实测。

## 下一步实机验收

1. 在家庭常驻 Linux / NAS 上确认蒲公英访问路径、网卡与子网广播。
2. 使用实际 PC / NAS 验证睡眠或关机状态下的 WoL，以及 TCP 端口恢复时间。

4. 实测 ARM64 内存、CPU、二进制体积与每日写入量，再确定路由器的最低要求。
