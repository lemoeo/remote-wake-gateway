## 与完整规划的交付边界

- MQTT、云端、outbox、Android、WebSocket 属于后续阶段，本次没有加入空模块。
- 文件锁实现覆盖 Linux / macOS / FreeBSD / Windows，UDP 广播使用 Go 标准库。macOS 回归已通过；Windows 原生 CI 已配置，尚待远端运行；Linux / FreeBSD 的新增路径与目标设备效果仍需对应环境验证。
- 使用规范 JSON 任务文件作为历史来源，尚未增加可重建 JSONL 归档。默认 stdout 日志，尚无文件日志轮转器。
- schema 不兼容时明确拒绝读取；尚无自动版本迁移器。备份和升级目前按 README 手工执行。
- 任务容量采用数量上限（10000 条，每文件另有 4 MiB 上限），尚无独立的任务目录总字节设置。
- 配置保存后的监听地址、public_url、并发/队列和保留策略需重启生效；名称和允许目标网段即时生效。设置页面会提示重启。
- CLI 初次设置密码、Web 初始化及本机停服恢复命令均可用；尚无 Web 管理员密码修改接口。
- 未测量 ARM Linux 的 RSS 和长期闪存写入量；未在真实 PC、Mac、NAS、树莓派或 OpenWrt 上验收。交叉编译通过不代表硬件兼容。
- 本机没有 Docker 运行环境，Dockerfile / Compose 和 systemd 模板尚未进行部署实测。

设备弹窗防误关闭已验证：添加和编辑时填写名称、MAC 地址，点击遮罩和按 Esc 后弹窗及输入均保留；底部取消和右上角关闭仍可正常退出。TypeScript 检查与生产构建通过，已更新内嵌前端和本机二进制。

六项可靠性修复：批次绑定连接与登录会话，提交响应返回前断线也须手动继续；取消删除不会关闭编辑表单；创建请求沿用幂等标识并在重启后识别重复请求，配置或密码冲突返回 409。设备变更的合并刷新现在传递实际查询失败，显示同步异常；手动刷新在 SSE 不可用时也按已知任务 ID 同步，不查询最近历史列表。新增回归覆盖这些时间顺序和失败路径。

历史接口改用创建时间 / 任务 ID 有序索引，仅复制当前页；游标含不可变排序键，锚点被清理后仍可分页，也兼容旧任务 ID。手动清理用独立清理锁序列化文件删除，不持有应用锁；自动清理每次最多 128 条并推送具体删除 ID。测试验证删除文件被阻塞时，设备查询、分页和任务提交仍可进行，且并发清理会被明确拒绝。

基准（本机 macOS arm64，10 万条记录，取 50 条，3 次迭代）：分页路径约 13.8 微秒 / 50 KB 分配，全量快照路径约 33.5 毫秒 / 43 MB 分配。可通过 go test ./internal/app -run '^$' -bench 'BenchmarkHistory(Page|FullSnapshot)100000$' -benchtime=3x -count=1 重现。此数据用于比较路径开销，未代表 OpenWrt 实机性能。

浏览器在独立临时服务中模拟首个创建请求落盘后断开响应连接，最终列表仅出现一台新增设备。原生删除确认框受当前浏览器自动化限制，取消 / 成功 / 失败三个关闭分支由设备编辑器单元回归覆盖。验证未读取实际数据、未发出唤醒指令。
